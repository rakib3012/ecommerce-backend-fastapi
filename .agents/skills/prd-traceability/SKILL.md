# PRD Traceability

1. Read the exact PRD source and preserve its terminology.
2. Record PRD section/page per requirement.
3. Inspect source and migrations for implementation evidence.
4. Mark IMPLEMENTED / PARTIAL / MISSING / UNKNOWN / CONFLICT.
5. Record evidence file paths and symbols.
6. Convert gaps into tasks and Given/When/Then acceptance criteria.
7. Identify conflicts and open decisions.
8. Build test matrix.
9. Never mark implemented because a filename/route exists; inspect behavior and tests.

PRD map: pages 1–3 product/stack/features; 4 DB schema; 5 APIs/NFRs; 6–8 roadmap and detailed tasks; 9 testing checklist/deliverables.
